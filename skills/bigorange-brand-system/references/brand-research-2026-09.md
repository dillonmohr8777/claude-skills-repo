## Recommendations for the brand system

- Fonts: use Raleway for headline/display roles (this is the confirmed live-site h1-h6 default) and Open Sans for body copy (confirmed live-site body font) across both web-matching decks/PDFs and any web-embedded surfaces. Where a Beaver Builder rich-text module specifically renders body copy, the live site actually shows Poppins (weight 300) rather than Open Sans for that one context — if the September package needs to visually match rendered page copy pixel-for-pixel rather than the theme's declared default, use Poppins for body blocks and reserve Open Sans for structural/system text (forms, meta, nav). For decks and PDFs, where "Poppins vs. Open Sans" ambiguity is undesirable, standardize on Raleway (headers) + Open Sans (body) since that is the CSS-declared theme default and the more defensible pairing to cite.
- Color: treat `#f68326` as the one confirmed brand accent/CTA color to build the palette around, with `#d66509` as its supporting shade (borders, hover/pressed states) and `#428bca` as the confirmed secondary/link blue. Do not introduce `#3b5997` into the system without further verification — it is not confirmed as intentional. For neutrals, `#333333` (text), `#000000` (footer/CTA text), `#ffffff` and `#f2f2f2` (backgrounds) are all directly confirmed from the live CSS and safe to carry forward.
- Per-surface rule: web/live-site work should match the Beaver Builder theme values above exactly (orange `#f68326` CTAs, Raleway headings, Open Sans/Poppins body per context). Decks and PDFs are not bound by the theme's CSS and can use the same palette and type pairing for consistency, but since no print/PDF-specific brand asset was found on the public site, the September package should treat any deck/PDF typography and spacing choices as new system decisions rather than something being "matched" from an existing print asset — flag this explicitly to whoever owns the September package so it isn't presented as verified brand continuity.
- Because no public pricing page exists, the September package should not attempt to reproduce or reference specific price points; if pricing needs to appear, source it directly from the client/agency rather than the public site.
- Because client case studies/logos were not found publicly, avoid fabricating named-client proof; if the September package needs social proof, use the confirmed award/certification badges and the "50+ 5-Star Google Reviews" claim (attributed to the site itself, not to Birdeye's differing count) rather than inventing or blending review numbers across platforms.
- Voice: calibrate copy to the mixed register actually observed — plainspoken/playful hooks and CTAs ("non-salesy," "What does not marketing cost you?") paired with proof-led, declarative expert statements in long-form content (blog posts). Avoid over-indexing on either the citrus/playful pole or the pure-consultant pole; the live site uses both deliberately by content type (page hero/CTA copy vs. blog body copy).
